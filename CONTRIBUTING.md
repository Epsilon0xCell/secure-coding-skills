# Contributing

Contributions that make the two passes sharper are welcome. The bar is the one the skills themselves set: show the work.

## Worked examples

The most valuable contribution is a new worked example under `examples/`. It needs:

1. A small, self-contained piece of code you wrote or have the right to publish. No code taken from a real project without permission, and no real target, employer, or client material in any form.
2. `FINDING.md`: the first-pass finding in the audit skill's format, with a traced flow and honest confidence.
3. `DISPROOF.md`: the second pass, a genuine attempt to kill the finding. Examples where the disproof succeeds are worth as much as examples where it fails, and an example where the verdict is downgraded or unexamined, honestly labelled, is worth more than either.

## Class references

A new reference file, or a sharper trap in an existing one, should be grounded in a case: a defect shape that really occurs in pull requests, or a false positive that really gets filed. State the case in the pull request description.

## Style

Plain prose, short sentences, no filler. If a claim in a skill file cannot be acted on by the agent reading it, cut it.
