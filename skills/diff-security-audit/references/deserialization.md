# Unsafe deserialization

Bytes an attacker can influence are turned into live objects, types, or code, and the format itself does the attacking.

## Where to look in a diff

- Native object serializers used on untrusted data: Python `pickle`, `marshal`, `shelve`, `yaml.load` without a safe loader; Java native deserialization and XML decoders configured for arbitrary types; .NET `BinaryFormatter` and friends; PHP `unserialize`; Ruby `Marshal.load`.
- Format features that reach beyond data: YAML custom tags, XML external entities (XXE) through a parser not hardened against them, JSON parsers that construct types named by the payload.
- Data that only looks safe: a cookie, cache value, queue message, or file the attacker can write through another feature and the server later deserializes.
- Signed or encrypted blobs whose verification is optional, ordered after parsing, or skipped on an error path. Parsing before verifying is the bug.
- Version and migration code that loads old formats with the old, wider parser.

## The two questions

1. Can an attacker influence the bytes, end to end, from something they control to the deserializer call? Server-generated bytes round-tripped through storage the attacker cannot write are a different risk class.
2. Does the format, as configured here, let the payload name types, trigger constructors or callbacks, or expand into something other than plain data?

## False-positive traps

- The safe loader or strict schema is actually in use: `yaml.safe_load`, a JSON schema validated before mapping, a data-only format with a type allowlist.
- The blob is signed and the signature is verified before parsing, on every path, including errors.
- The input is a trusted internal producer on an authenticated channel, and the finding would need that channel compromised first. State that precondition honestly rather than dropping the note.

## What good looks like

Plain-data formats (JSON with a schema), safe loaders, type allowlists, and signature verification before parsing. The strongest fix removes the powerful format from the untrusted path entirely instead of trying to tame it.
